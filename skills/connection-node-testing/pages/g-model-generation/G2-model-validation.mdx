## G2 — Model Validation

**Category:** Model Generation | **Tests:** `<Var>` from 5 tables + cross-table validation in `<Script>`

Validates an ETABS model by reading connectivity, properties, and coordinates.
Checks for missing elements, undefined materials, and floating joints (nodes
not connected to any frame).

### What this tests

- `<Var>` tags from 5 different tables simultaneously
- `parse_table()` called 5 times in one script
- Cross-table validation logic (joints vs frame connectivity)
- List comprehension with `any()` for membership testing
- Issue accumulation pattern (empty list = pass)
- Large data processing (iterating all joints against all frames)

### Prerequisites

1. Any ETABS model — works on new models, imported models, or AI-generated models
2. No analysis required — reads geometric/property data only

### Expected behaviour

- Element counts: `frame_count`, `area_count`, `joint_count`
- Property lists: `mat_names`, `sec_names`
- `floating_joints` — list of joint names not connected to frames
- `issues` — list of problems found (empty if model is clean)
- `validation_summary` — comprehensive one-line model report

### Note

The floating joint check does O(joints x frames) comparisons, which may be slow
on very large models (1000+ joints). This is intentional for testing script
execution time limits.
